## S-2 不得为迁就新代码而放宽既有契约（never weaken an existing contract）

**规则**：新功能导致既有断言失败时，先判断是**新代码错**还是**旧断言过时**。属于旧断言的，必须保留其原始意图并另写用例承载新行为；属于新代码的，改新代码。禁止直接改期望值、删断言或改键位绑定来让新代码通过。

**来源**：Q-001（把 `'lin'` 改成 `'line'`，等于删掉一条覆盖）、W37（把 Shift+Enter 改绑 `selectionCopy` 并改动既有换行测试）、W38（W37 期间误删 ctrl+enter 绑定）。三次同因。

**验收检查**：diff 里每一处既有断言的改动都能说明「原意图由哪条新断言继续承载」。

## S-3 渲染产物与条目文本分离（separate render artefacts from entry text）

**规则**：复制、提取、序列化用户可见文本时，必须区分「终端渲染产物」（缩进填充、换行折叠提示、续行填充、tab 展开）与「条目本身的文本」。渲染产物不得进入复制结果，条目文本不得被静默丢弃。

**来源**：Q-004（续行前缀填充被当成文本、显式换行前缀被误删）、W37 复核缺陷（键盘复制复制了被裁剪的不可见文本）、W37 tab 偏移（tab 展开改变鼠标列）。三次同因。

**验收检查**：每个提取函数都有对「续行 / 显式换行 / tab / 宽字素 / 折叠提示」的显式用例。来源画出的ANSI行交给按列宽限定的帧宿主，不再用纯文本字素裁剪器计入SGR参数；新增颜色展示必须用实际窄屏解码格核验（Q-041）。新增宿主预清理必须在来源归一化之前保留CR/tab/NFD等原输入，转换顺序分别由原输入与精确提交探针核验，避免来源函数收到已丢失字符（Q-047；Q-004同属原文/产物混淆）。

## S-4 状态与资源必须有明确归属和重置点（explicit ownership and reset）

**规则**：任何跨调用保留的状态（点击序列、草稿槽、粘贴缓冲、选择、输入 owner）与任何被接管的资源（进程组、管道、终端模式、锁）都必须写明：谁创建、谁释放、何时重置、异常路径如何收尾。跨断言/跨实例的状态必须在用例边界显式重置。实际CLI的当前会话须绑定持久metadata及活动锁，不按随机UUID文件名的顺序选择历史记录（Q-056）。后台分析或工具请求超时/取消后，必须复查实际进程、资源占用及所有权；请求已结束不等于计算已停止。清理仅针对已核验归属的PID/进程组，并验证退出。

**来源**：Q-003（点击序列与「复制后取走选择」跨断言污染，导致后续断言在脏状态上运行）、W39 粘贴跨界（未完成 paste 的尾串被当作审批键）、W36 smoke 挂起（驱动只杀直接子进程，`script` 被 init 收养并持有管道）。三次同因；Q-018进一步暴露工具请求结束后服务计算残留，Q-019再次命中跨操作状态未重置。

**验收检查**：新增状态字段在类里成组声明并注明重置点；驱动脚本记录 PID 与进程组并在 `finally` 收尾；异常任务结束后保存已退出或仍活跃的进程核验结果。终端关闭/绘制失败必须同时核验活动模型或工具请求取消、交互loop完成及会话锁释放，终端模式恢复本身不足以证明整链清理（Q-027）。复用屏幕缓冲区的容量与活动height分别核验，导出不得读取活动帧之外保留的旧槽；窄→宽交替重排检查最后一行原文（Q-042）。终端交接必须等待继承stdio的后代进程退出再恢复输入/删除临时文件；异步输入owner在action触发时同步建立，剩余同批decoded动作丢弃，outer cleanup等待释放（Q-053；Q-027同属资源owner遗漏）。持久文件的异步读写/retry必须固定目录与会话owner；rebind不得清未成功保存的旧pending，临时故障修复后保留重试机会，崩溃锁回收核验进程与文件身份；新增用户目录消费者时所有真实交互fixture须显式私有临时userDir（Q-062；Q-056同属owner边界）。

## S-5 断言与期望必须绑定稳定不变量（assert on stable invariants）

**规则**：测试与驱动不得依赖具体列宽下的截断结果、瞬时帧内容或渲染时序。等待条件要绑定稳定不变量（进入备用屏、命令提示、状态词），而非某一帧恰好出现的字符串。

**来源**：W36 等待被 40 列裁掉的横幅、W40 smoke 超时（40 列状态行把 `Model: fixture/other` 裁成 `Model: fixtu`）、W36 等待瞬时流式帧。三次同因。

**验收检查**：新增等待条件都能说明在最小支持列宽下仍然成立；对来源分支的验证须有可区分的反例，移除关键条件应使对应夹具失败；复制校验须把必需范围和导出绑定到实际plan/ledger/product，不能仅证明来源中存在正文（Q-071）；服务端握手锁定待验阶段，状态行只用各宽度共有的可见前缀，完整结果由会话记录核验（Q-026）。错误状态等待须先实测状态行的实际大小写与前缀，展示文字中的Error不等于状态标签error；独立running/ready标签与错误正文分别实测，error正文不会自行改变运行状态标签（Q-038）；文件/配置失败合同另由持久状态验证（Q-032）。query/flush回退须按每条哨兵完成阶段验证；颜色断言按来源mux/attacher色彩级别实测，RGB与ANSI256模式分别核对（Q-034）。内容断言保留原文；空提示/状态等待仅归一化无内容的填充或NBSP，不能把渲染填充当作提交正文（Q-029）。轮询JSONL时按完整换行记录判断可用：新文件和未完成尾条保持pending，已完成记录仍严格解析；文件存在本身不代表metadata已提交（Q-030）。

## S-6 新增结构时同步所有读取点与驱动（keep every reader in step）

**规则**：新增或改变一个数据结构、字段或流程步骤时，必须在同一次改动里找出并更新**全部读取方**：生产者类型、消费该结构的每个函数、渲染路径、以及驱动脚本与测试里的按键/输入序列。类型检查通过只是最低门槛——类型正确但读取点仍读旧字段（或驱动仍按旧步骤走）同样算违规。

**来源**：Q-002（读取 `cells()` 的 `segment` 而未声明该字段，`tsc` 三处报错）、Q-009（新增 `groups` 后 `handleDialogAction` 仍读 `request.choices`，整条分组问答被判定为文本输入）、Q-011（分组问答新增回看页后，`--dialogs` 驱动仍按旧步骤走而超时）、历史提交 `d7c7be0`（TUI keymap 测试的上下文列表缺类型）。四次同因。

**验收检查**：生成器输出目标须显式指定并在写入前校验，批量重生成校验写入独立临时目录，再与产品逐字比较，避免默认目标覆盖（Q-069）；新增字段/步骤的声明、读取、渲染与驱动改动在同一 diff 内；`npm run check` 通过；每个受影响的驱动脚本实跑一次；同一CLI的TTY默认交互与pipe显式交互入口分别核对，不把TTY默认门控照搬到pipe驱动（Q-032）。新增测试先核对文件已有helper/import，复用等待工具；可能为空的来源结果先显式收窄，类型检查与行为回归同时通过（Q-035）。显示/原文双结构须核验删除引用后字面重输、跨clear的kill/yank和原内容历史搜索；单纯显示标签匹配不足以证明读取链完整（Q-050）。input owner同批切换时，剩余已解码报告必须按其终端owner分流，旧文字继续丢弃；decoder.discardPending只覆盖未完成framing，不能代表已解码actions已处理（Q-060）。startup新增async加载时，首次输入等待真实listener就绪，加载置于既有cleanup边界内；测试保留原精确输入与取消断言，核验低层模块新增依赖未形成初始化cycle（Q-062）。生成副本的每个 import 名字须按名解析到**声明它的**模块（跨 chunk 别名不存在单一归属时不合并文件），未声明零只证明闭包成立、不证明来源正确——Q-089 里 15 个名字全挂在同一副本上，扫描报 0 而运行时 `does not provide an export named '$8e'`。

## S-7 能逆向的全部逆向，先搬运再适配（source before invention）

**用户硬性要求**：「能逆向的全部逆向，不要闭门造车」「不要担心引入外部依赖」「项目的最终目的就是完全复刻 claudecode，只是换了换函数名」「和 claudecode 做法完全一样就可以」。以样本实现与行为为基准，不限制必要外部依赖的数量。该要求覆盖功能本身及其依赖，包括布局引擎、渲染器、状态机、文本处理和宿主桥接；不得因模块体积、压缩命名、打包头或既有实现方式而跳过来源核验。

**开工门槛**：用户要求「每个任务动手之前都要确保自己不是在闭门造车，而是先确保能逆向源码」。每个任务在修改产品代码之前，先在该包记录中完成来源核验：样本与模块身份、已取得的实现正文、入口及坐标、直接和传递依赖、门控与正常/失败/取消/清理合同、可复制范围及具体宿主适配点。证据尚缺时继续定向逆向调查；不得先自写近似实现，再补来源理由。恢复中的任务先复用并核验已有记录，避免重复全库调查。验证驱动和文档维护以其验证的来源合同为依据，同样先核对当前实现。

**强指令（2026-10-14 用户明确要求）**：来源正文可取得时**必须**先按来源实现，禁止自行推定。具体为三条硬约束：(a) 修改任何按键/状态/流程分支前，先读出**拥有该分支的来源正文**（模块摘要+范围+坐标单位），按其条件、默认值和吞掉/透传规则落地，不得凭症状反推后自写分支；(b) 缺陷定位必须落在来源路径上——先证明是哪条来源分支没被满足（哪个 action/键/状态未映射），再改产品代码；只凭观测到的症状（行数、帧内容、断言差值）写假设并据此修复视为违规；(c) 每个被改动的处理函数在代码注释里注明所依据的来源范围，包记录里注明该范围与摘要。

**规则**：先定位样本入口、核验摘要和坐标，追齐直接及传递依赖、门控、状态和清理链，再选择搬运方式。优先复制可独立提取的实现；其次保留原算法并替换必要宿主接口。自行重写前必须有具体证据说明原实现为何尚未取得或与用户明确约束冲突。Node 运行、中立产品命名、当前依赖数量和 `@bun @bytecode` 头都不等于排除 React、Ink、Yoga 或 JavaScript 布局核心；不得把自行推定的技术偏好写成用户限制。

**来源**：用户本轮明确要求；Q-014（W35 以未经核实的“六依赖 / Bun 必需”限制跳过布局核心）、Q-015（W43 未追齐预览依赖便自写渲染与行数逻辑）、Q-067（Q-066 按症状假设「扫描被二次重启」并据此准备改 `start()`/`accept()`，实际来源路径是 gLt 的 `return`→`onSelect` 未被宿主 handler 映射，产品 handler 还自造了 gLt 明文否定的 cancel-on-empty 与 backspace-exits 行为）、Q-068（W45 尚未读取完整闭包即用 typeof 替代原生检测，同模块完整1660单位依赖实际可直接复制）、Q-079（W45-8 手写适配的 `carryPaint` 抄漏 `a7o`，编译/类型/驱动前四条断言都不报，只有逐字符 diff 来源才暴露）、Q-081（W45-8 给产品自造了「按行裁剪 run」的 `inputLineRanges`/`paintPromptLine`，理由是「产品没有 base span」；读源后该分支不存在——来源是起点列表 `getRenderedRowStartOffsets` + `S9r` 偏移映射 + 光标过滤）、Q-083至Q-085（W45-10 的门控与注册表宿主面：有默认值的取来源默认，无宿主面的显式关闭并记因，读不存在的注册表的一律做成入参而不近似）、Q-086（W45-11 其余 15 个核心与 34 个站点读的是本产品没有的注册表，成对补齐而不先造一半——源 `Mm` 就是站点与核心成对构造的）、Q-087（W45-12 起三个手写经典站点要拖 lodash `pickBy`/`baseIteratee` 子树、七个值事件被源表手写覆盖——按源自己的划分取包，不搬的部分成组记因；W45-13 把七个值事件按其手写描述符补齐，Q-087 收窄为三个经典站点），以及 Q-007 / Q-010 中近似行为偏离来源的事故。

**验收检查**：每包列出已核验的入口与依赖范围、摘要、坐标单位和搬运分类；复制正文与来源做摘要或差异核对；**手写适配的来源正文（生成文件之外的宿主适配体）必须与来源区间逐字符 diff**，注释坐标不能替代比对，因为生成文件的摘要核验覆盖不到手写分支（Q-079）；每个适配 / 重写有具体接口理由和行为差异；来源关键算法已有时禁止凭效果近似重造。缺陷记录必须指明未满足的那条来源分支及其坐标；被改动的 handler 注释含来源范围。先完成完整使用链，再用自有 fixture 和实际 CLI 验证；提取目录保持只读，恢复的应用入口不执行。
