## Static event consumers

| Event | Static observed behavior |
| --- | --- |
| Stop | Exit 2 and decision:block feed continuation feedback. continue:false prevents another turn. Nonempty additionalContext also requests continuation. Re-entry uses stop_hook_active:true. Main loop has turn bounds and a separate consecutive block cap, default 8. Plain successful stdout is display-only. |
| StopFailure | Collector results are discarded by the caller; no retry is implied. |
| PreCompact | Exit 2 or decision:block cancels/skips compaction. Successful unblocked raw stdout becomes compaction instructions, including raw JSON text. continue:false is ignored. |
| PostCompact | Compaction is already committed. Results contribute to display, not new model context; blocking flags are ignored. |
| PostToolUseFailure | Blocking error/context becomes model feedback. The inspected failure wrapper does not consume preventContinuation. A failed tool effect is not undone. |
| PostToolBatch | Ordinary path adds context then stops before the next model call for block/preventContinuation. An alternate explicit end-turn path discards those flags. |
| SessionEnd | Does not block or restart shutdown. Runner has a bounded abort signal and clears hook registry. Failed outputs may be displayed. |

Common synchronous output fields include continue, suppressOutput, stopReason, decision, reason, systemMessage, terminalSequence and optional hookSpecificOutput. Async output uses async/asyncTimeout. Streamed translation and one-shot collection are different implementations; callers consume their results differently.

## Independent integrated implementation

The independent schema accepts 33 event names with mixed flat definitions and nonrecursive matcher groups. Command, HTTP, prompt, agent, synchronous script, trusted named callback and read-only mcp_tool definitions are accepted; async ownership applies to command hooks. Both matchers apply in order, and total entries/flattened definitions are capped at 1024. All types accept once. The independent script/callback/MCP contracts below differ from the complete original transports and consumers.

Current source dispatch includes SessionStart, UserPromptSubmit, UserPromptExpansion, PreToolUse, PermissionRequest, PermissionDenied, PostToolUse, PostToolUseFailure, PostToolBatch, PreCompact, PostCompact, Stop, StopFailure, Setup, InstructionsLoaded, SubagentStart/SubagentStop, TaskCreated/TaskCompleted, WorktreeCreate/WorktreeRemove, FileChanged, MessageDisplay and SessionEnd. Interactive transitions emit PreModelSwitch, PostModelSwitch, ConfigChange and CwdChanged; Notification, TeammateIdle, DirectoryAdded and Elicitation/ElicitationResult now have the finite owning integrations below.

| New transition | Independent consumer |
| --- | --- |
| Notification | Observes runtime notifications between completed turns; additionalContext is displayed. Its verdict does not suppress the notification task. |
| TeammateIdle | Only explicit local idle subscriptions generate this event; blocked/stopRequested suppresses that queued notification turn, without changing the teammate task status. |
| DirectoryAdded | Post-relocation observation after /cwd or main worktree enter/exit and runtime rebuild; no arbitrary filesystem watcher or relocation rollback. |
| Elicitation | Active interactive form requests only; blocked/stopRequested yields decline before reading terminal input. |
| ElicitationResult | Observes the validated accept/decline/cancel result on the non-aborted normal form path; cancellation/errors return cancel without guaranteed result-hook delivery. |

CLI --mcp-elicitation requires --interactive and pins mcpClient.elicitation. The form presents a bounded schema/message and accepts JSON, :decline or :cancel with at most three attempts. Startup, idle notification turns, headless and absent active callbacks return cancel. URL elicitation remains outside this contract.

Optional --watch-config observes exact loaded instructions/rules/imports plus settings/catalog/keybindings and queues /reload at completion. Prompt/agent/callback/MCP resolver invocations share a 16-stage cap per actual HookLifecycle. Timeout/abort returns to the caller while retaining a slot until the underlying promise settles; once claim persistence occurs before resolver effects. MCP connection and host-factory stage caps are separate ownership bounds. Shell script transport does not become a general Workflow script runtime.

Prompt uses one tool-free model evaluation; agent uses eight calls/32 tools per batch with the existing read-only surface, permissions/cancellation/context/native block checks. Historical759/879/948 cover their versions; continuous resolver/events use owned fixture and earlier156/156 affected evidence in STATUS.md. These bounds and verdict protocol remain independent contracts.

- Shared event/schema definitions validate stored sessions strictly while the settings loader drops unknown event keys. Old optional fields remain absent; journal validation preserves raw key order.
- Flattened identities preserve event, original entry/inner positions and a SHA-256 of the definition/group matcher; pinned configuration is not removed or rewritten after consumption. HookLifecycle claims are owner-local and journal hook_once synchronously before the first command/HTTP/model/async effect. Same-Session Agent wrappers share lifecycle state, resume restores consumed keys, and a new session/fork starts fresh. A claim interrupted after persistence is already consumed; this is at-most-once attempt behavior, not a guarantee that the effect completed. Mismatches, pre-abort and missing resolver/owner/header prerequisites do not consume a key; failures after a claim do.
- Skill overlays validate the merged parent/skill total before shell expansion, child journal creation or hook effects. Flattened grouped skill command hooks also receive command permission preflight before those effects. Child/skill journals own their lifecycle independently; continuation of the same child session retains its claims.
- Hooks receive newline-terminated JSON stdin and have bounded output/process lifetimes.
- Tool effects/results are journaled before post hooks. A post-hook output replacement receives a separate durable tool_output record and is reused during interrupted-batch recovery. PostToolBatch fires after the complete ordered result message.
- TaskCompleted and WorktreeCreate gate effects before execution; PermissionRequest updatedInput reaches execution after an input-policy recheck. TaskCreated/FileChanged/WorktreeRemove currently provide bounded post-effect observation, not filesystem rollback.
- SubagentStop replaces Stop for child turns and consumes continuation feedback within maxTurns. SessionEnd remains a shutdown observation.
- Failed executed tools fire PostToolUseFailure. Its feedback reaches the next model request while the original tool error remains intact.
- Stop blocking/context continues the same task within maxTurns. Explicit continue:false ends the turn. Completed Stop decisions are reused during recovery; interrupted Stop commands are not replayed.
- New SessionStart context on --continue follows recovered tool results. Context collection stops at a completed turn boundary.
- PreCompact instructions enter the summary request; blocking prevents it. PostCompact output is displayed after the new summary epoch is committed.
- Model errors fire StopFailure while leaving the turn resumable. A saved failure stop does not replay an already-started StopFailure command.
- CLI, interactive transitions and child/skill sessions fire SessionEnd before closing journals. Its independent shutdown signal has a 2-second deadline; cleanup releases resources/locks if it fails. Parent and child async registries own command cleanup; completion routing is separate from permission gates.
