RTe registers resources changes only for resource-capable connected clients. It invalidates both resource caches,fetches both concurrently and keeps previous values for each failed family independently. The epoch/current-client guard runs before and after fetch. applyQueuedUpdates treats undefined as keep,empty as delete and checks current client identity. T2e executes the first request immediately,coalesces arrivals into one queued refresh,waits1000ms after completion and doubles queued delays to30000ms,resetting after idle. hme skips a detached transport.

Design Ground/Sketch/Agree: existing McpClient routes tools changes through each transport and ManagedMcpClient,while TUI reads its resource catalog once. CandidateA makes TUI refetch the whole list on invalidation;it scatters partial-failure and generation rules into the UI and refetches healthy peer servers. CandidateB owns per-server snapshots/queues on the connection and publishes typed listing updates. B is chosen under Model the Domain. Existing managed state supplies transport identity;source timer/queue owns refetch. Terminal subscription resets W339 pending values and repaints without editing the draft. No new model tool,account service or subscription protocol is added. HTTP uses only existing POST/opted-in GET streams.

Throughput checkpoint:
- Blocking first steps: exact source/identity acquisition and actual compiled missing-refresh baseline precede product writes.
- Independent workstreams: main owns the coupled implementation and fixture;one bounded independent reader reviews the validated artifact.
- Shared mutable state: one connection-owned queue per server,one subscription per terminal,existing managed client owns transport replacement/close.
- Smallest safe decomposition: resource-only queue/snapshot owner over existing transports;source scheduling does not become a generic event framework.

Lazy first catalog read remains,instead of eagerly fetching every connection.
