## Contract and boundaries

An authored body may express shell as a fenced block or as an inline span; both are found in the authored text, both are preflighted before the first effect, and both are replaced by their command's output in document order. A fenced block is recognized without any feature flag change, and `skillRequiresExecution` reports a body as executable on the same rule the executor uses, so a caller never asks for an expansion that would not run. A span inside a block is skipped, so a block runs exactly once even when its own text looks like a directive, and output text is never rescanned. Whitespace and CRLF inside a block are normalized before the command is shown or approved.
