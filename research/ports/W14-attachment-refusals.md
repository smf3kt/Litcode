Classification: copy of the classifier's categories and of the two refusals this runtime lacked, onto the media read path it already owns. `src/media.ts` already refuses an escaping path, a symlinked path, a reserved directory, a non-regular file, an oversized file, a file that moved between validation and read and a file that grew during the read - so the recovered set maps onto it almost one for one, and the two members that had no counterpart were `credential_name` and `hard_links`. Owned decisions, marked as such:

- **The check runs before confinement, on the text the caller supplied.** The recovered classifier takes the path as given and reports the segment; here `credentialShapedSegment` is a pure function of the requested path, so a refusal never depends on what the path resolves to and cannot be reached by a name that is only credential-shaped after symlink resolution. The resolved path is still what is opened, and confinement is unchanged.
- **A transliterated list rather than the recovered arrays.** The recovered sets are internal constants of a 697 KB module; the readable part is transcribed here with the same spellings, and the host-specific members are named in the port record as not ported rather than guessed at.
- **The segment is reported, not just the verdict.** The refusal quotes the segment that matched, because "its name or folder is one that credentials are kept under" without saying which leaves a person guessing whether the folder or the file tripped it.
- **The sample exemption is applied to the basename only.** The recovered exemption list drops names that announce themselves as examples; here it is tested per segment, so `.ssh/example.env` is still refused for its folder - an example inside a credentials directory is still inside a credentials directory.

## Contract and boundaries

An attachment whose requested path contains a segment that names a credentials store, a key, a secret file or a credentials folder is refused before the filesystem is touched, and the refusal names the segment that matched and tells the user to attach the file themselves. A name that announces itself as an example, sample, template or distribution copy is not credential-shaped. A file with more than one hard link is refused when it is opened, because the validated path is not the only way to those bytes; the refusal says to copy the file and attach the copy. Everything the reader already guaranteed is unchanged: workspace confinement through every ancestor, no symlink at the leaf, a regular file, the byte cap, and the device-and-inode re-check against the handle.
