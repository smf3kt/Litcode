# W304 local sign-in and unconfigured start

Status: verified locally on 2026-10-23. Explicit user request: do not refuse to start when no LLM configuration exists, and support DeepSeek sign-in. Local implementation, validation and commit only; no push, no attribution trailer.

Task card.
- Entry and outcome. A live interactive session with no credential and no model opens and runs; the first model turn is refused with a sign-in hint and leaves no half-written turn. `litcode --login deepseek` and `/login deepseek` store a working credential; a later session uses it with no environment value.
- Provider facts. DeepSeek documents an API key sent as `x-api-key`, base `https://api.deepseek.com/anthropic`, and models `deepseek-flash` and `deepseek-v4-pro` (api-docs authentication, list-models and anthropic_api guides, read this session). No OAuth authorization server, device flow or token endpoint is published.
- Targets. `src/login.ts` (new), `src/cli.ts` (startup gate, credential resolution, `--login`/`--logout`, provider slot), `src/interactive.ts` (`/login`, startup notice, provider-blocked turn gate, help text), `src/tui-autocomplete.ts`.
- Boundaries. `LLM_API_KEY`, a flag, settings and a compatible client's own configuration all outrank a stored credential. A stored credential is used only for the endpoint it was issued for. One-shot tasks still fail fast, because there is nowhere to ask. `--resume` keeps its pinned endpoint.

Source preflight. The recovered sample (2.1.296, SHA-256 `c9b5341637becbd423ddffc5b254afb645682a3868cb708bbc6cc0e7bb419937`) has no DeepSeek path and its own sign-in is Anthropic account OAuth, which stays excluded. This package therefore adds a local adapter instead of porting a recovered body; the reason is recorded here per S-7.

S-7 exception. Recovered OAuth code in `chunk-rx2nah4x.js` (`claude_authenticate`, `claude_oauth_callback`, `requestOAuthTokenRefresh`) targets a vendor account service. The user asked for DeepSeek, which publishes no such service, so no obtainable source body implements the requested behaviour. The generic authorization-code + PKCE loopback flow is implemented from the protocol itself (RFC 6749 §4.1, RFC 7636) with `node:http` and `fetch`; the DeepSeek profile is the documented key flow. No account, subscription or hosted-service call is added.

Implementation.
- `src/login.ts` owns the profile table, the credential store, the login flows and the provider factory. `LOGIN_PROFILES.deepseek` carries the documented endpoint, header and models; `oauth` and `custom` cover a gateway that runs an authorization server or any other compatible endpoint.
- The store is `<userDir>/credentials.json`, `version: 1`, `active` plus a `providers` map, written through `atomicWriteFile` with mode 0600 and re-chmodded. A missing, linked, oversized or malformed file answers an empty store rather than an error, so a damaged file cannot stop a run.
- `runLogin` writes the credential and returns it. `readStoredCredential`/`storedCredentialFor` read it back; `removeStoredCredential` deletes one entry, and the file with the last entry.
- `createProviderSlot` is a stable `ModelProvider` the loop, runtime and agent already hold. Until a credential is adopted, `complete` rejects with the sign-in message and `count` answers 0; `/login` calls `adopt`, so no runtime, session or agent rebuild is needed for the credential itself.
- `OAuthProvider` renews an expired access token from its refresh token before a call, retries once on a 401, and writes the refreshed value back to the store.
- `src/cli.ts` resolves a stored credential below every explicit source. The interactive start no longer requires a credential or a model: a missing model becomes the sentinel `unconfigured`, and the loop refuses a turn through `providerBlocked` before the prompt is journaled. `--login`/`--logout` are complete actions that return before session work.
- `src/interactive.ts` adds `/login [deepseek|oauth|custom]` over the session's own dialog surface, adopts the credential, moves the live endpoint to the credential's endpoint, adopts the credential's model when the session had none, and shows the summary in the transcript. `COMMAND_HELP` and `TUI_COMMAND` gain the command.

Credential handling. No value reaches a journal, an event, a status line or a notice: the startup notice and the sign-in summary name the provider, endpoint and model only, and the driver asserts the key is absent from terminal output and from every journal file. The browser is opened only when a display is plausible (`LITCODE_NO_BROWSER`/`CI` suppress it) and the URL is printed regardless.
