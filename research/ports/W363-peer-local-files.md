## Host shape and decisions

The file wire schema owns path, file_name, nonnegative file_size, lowercase SHA-256 and optional media_type. Tool input is address, files and optional message. Types are derived from schemas. The existing peer transport takes optional already-staged files; it owns frame encoding and delivery. A separate file module owns staging, integrity, spool sweeping and materialization. The existing Session supplies live feature/id getters; no additional queue or background manager is created.

The permission adapter exposes the files a tool will read and feeds each through the existing read_file permission decision before the send decision. Deny wins over all asks; asks retain the normal Agent approval pipeline. Workspace and explicitly granted directory confinement stays in the existing file-path owner. This adapts ag/IA rather than creating a second permission engine.

The source upload root is outside this host's workspace-relative read_file contract. Received files therefore live under workspace .harness/peer-uploads/<session-id>, with workspace-relative quoted references in the model text. Their bytes and message references remain after a clean exit for cold history. Stage copies use userDir/file-transfers, source sweep age/cap and source delete-only-own-spool behavior. No account/cloud download surface is ported.

Candidate A uses the existing transport and permission pipeline with one typed file boundary. Candidate B carries raw file bytes through messages or creates a second sender, which changes the source wire format and duplicates pacing/identity/receipt ownership. A is selected. Existing file confinement is retained as an explicit host constraint; network paths use the current local path owner and source path preflight. MIME labels are metadata only. Telemetry is omitted.
