## Ground and design

config.expandSkill owns all substitutions. executeSkill uses it for both the instruction body and child context budget. CLI settings and original session metadata pin quotedArguments and extendedArguments independently. The existing quotedSkillArguments is a hand-written quote-group parser; the prior ledger explicitly records the source AST closure as unresolved. That premise is now obsolete because the pure parser and complete extraction closure are obtainable.

Candidate A keeps the exact parser in its own generated module and exact extraction helpers in a second module. A typed function returns only string[] to config. Candidate B embeds the same large parser inside config.ts. A keeps minified names isolated, avoids importing unrelated shell permission code and leaves a single argument owner. B grows config by 61,205 units and risks name collisions, so it is discarded. No worker fanout or architectural panel is needed under the project direct-execution rule.

The owned comparison confirms conflicts with existing pinned quoted arguments for incomplete quotes, substitutions, escaped dollar signs and operator boundaries. Preserve that path and its assertions. Add one optional pinned feature skillSourceArguments. Fresh CLI sessions default it on when no legacy argument feature is authored; explicit source selection wins. Old absent metadata and authored legacy argument settings keep their prior expansion. A deliberate reload re-resolves the version from current settings. Source mode calls complete copied uHe, including zero-based positions, named arguments, sentinels and fallback. The generated module also copies zH/rY [435100,435128) and gl from manifest-verified chunk-ax7r0qj7.js [677,739), SHA-256 8e782f9b216f270b08ab23c9d3724965dccfdaa6053e78d89103b7fc1926c67e. This versioned boundary is necessary to preserve original session fingerprints and observable legacy behavior.
