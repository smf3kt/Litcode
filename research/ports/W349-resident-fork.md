## Ownership and choices

Candidate A ports the full daemon/PTY stack, including job metadata, authenticated rendezvous, raw input, ring output and restart. It is the source's broad execution model, but introducing half its lifecycle in this package would leave several missing consumers. Candidate B preserves the source's ordinary REPL, omitted initial prompt, one queued turn and explicit exit using the host's existing interactive and authenticated same-host transport. B is selected for this finite local chain. It does not establish full daemon or PTY parity.

Source local-only narrowing retains peer provenance instead of human supervisor authority,and unattended human-answer prompts return their existing cancelled/denied outcome until a full attach owner exists. The source-shaped lifecycle/queue portions are adaptations;the privateIPC readiness replacement is a rewrite of an unavailable daemon backend. It is not classified as a copied implementation.

The optional residentForks field is a compatibility selector and is absent by default. New settings, strict stored metadata and explicit reload share that optional field. Original resumes never reload it. Only mode:'fork' uses it; `/background` retains its seed fallback and one-shot lifetime.

A source-backed preflight change also covers worktree relocation from an active peer-enabled parent. gft snapshots the accepted live tools; the host's relocation identity guard previously rejected the exact peer extension. The fork caller now passes its actual mounted peer tool definitions. completedHistory reconstructs only that exact schema extension over the committed metadata and compares the complete configuration; other mutations and ordinary relocation without an explicit extension retain their prior rejection. The target still rebuilds its own Runtime tools.

The worker owns its original journal and one authenticated ref'ed local inbox. Resident spawn adds a private process IPC readiness message after inbox/session publication; the parent awaits that message before painting success, then disconnects. A ten-second local startup deadline terminates the owned child on failure and retains its journal for inspection. The IPC message carries only its kind and session UUID, never tokens or credentials. The parent owns neither resource after detach. SIGINT/SIGTERM use the existing CLI AbortController; interactive finally closes peer resources, runs SessionEnd, releases Runtime and closes Session. The source `_e` retains the REPL through its PTY; ref'ing the existing inbox is the explicit local lifetime adapter. No synthetic pending Promise or new timer is used as residency.

Later UDS text keeps existing peer provenance, mode comparison, held expiry and slash-command exclusion. It is not promoted to the source supervisor's human rendezvous authority. Initial argv task is a distinct user task after any SessionStart message, never the previous seed or a substituted hook message.
