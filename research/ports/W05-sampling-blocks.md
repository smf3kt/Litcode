## Contract and boundaries

Accepted: `annotations` (audience entries limited to user/assistant and at least one entry; priority a finite number in 0..1; lastModified an offset ISO timestamp) and `_meta` (a JSON record) on text, image and audio sampling blocks, plus `_meta` on messages. Rejected with the existing bounded error before any callback, approval, token count or provider call: unknown annotation keys, an empty or non-role audience, an out-of-range priority, a non-timestamp lastModified, a non-record `_meta`, `tools`, `toolChoice`, and tool_use/tool_result blocks.

Metadata is inert: the transport passes the validated params to the callback unchanged, the host rebuilds text blocks as `{ type: 'text', text }`, image blocks as native base64 content plus an attachment reference, and never forwards `annotations` or `_meta` into the provider request or into the session journal. Block and message counts, the 32 KiB input cap, the 128-block cap and the existing text/image/audio gates are unchanged, and a rejected request still spends no sampling provider call.
