## Contract and boundaries

Canonical base64 must roundtrip; each clip is limited to 16 KiB and 4 clips per request, all under the existing 32 KiB JSON request cap shared with images and arrays. The declared MIME must name the container the signature check identifies; parameters after `;` are tolerated and the sniffed container supplies the reported media type. wav, ogg, flac, webm, m4a, aac and mp3 are recognized by signature; anything else is refused before any provider work. Gating order is unchanged: sampling off refuses, samplingAudio absent/false refuses, arrays off refuses array payloads, and the managed snapshot wins over authored settings.

Accepted bytes are published to the workspace-private attachment store (.harness/attachments, 0700, 128 files and 64 MiB, O_EXCL|O_NOFOLLOW temporary file with atomic hard-link publish) and the model receives only `[Audio from SERVER] Binary content (MEDIA_TYPE, SIZE) saved to PATH` with a workspace-relative path. Audio never becomes a native Messages block, and sampled audio bytes are not copied into the parent session journal. When the store cannot be opened or the clip cannot be published, the payload degrades to the "was not kept" text and nothing is written outside the store.
