## Implementation

`src/setting-writes.ts` reuses the existing recovered `Oe` signal copy from `plugin-chain-registry-stores-source.ts` (byte-identical body, already verified at W331) and publishes one frozen `{file, present}` record per committed document. `present` is computed through the shared `normalizeSettingsDocument`, so invalid `preferredNotifChannel`/`promptSuggestionEnabled` leaves never count as content, matching the loader. Subscriber exceptions are isolated by `Oe` and additionally swallowed at the publisher so an already durable write never reports failure.

Nine dedicated writers call `publishSettingsWrite` after their successful atomic write and before returning: theme/editor/diff/effort/autocompact/model/model-effort/permission-default (`theme-settings.ts`), focus view mode, scroll speed, stash latch, skill overrides, plugin toggle, prompt-suggestion backoff, auto-mode rules, and both permission canonical and legacy documents. Generic `atomicWriteFile`, the write queue, MCP state, approvals, spinner history and ordinary file tools do not publish.

`Session` keeps `liveSettingSources` separate from `config.settingSources`. The observer resolves the same path set the loader uses (`permissionSettingsPaths` plus the explicit settings file), matches only those absolute paths, and recomputes local presence across the canonical and legacy local documents with `settingFileHasContent`. That helper mirrors `HR`/`Uw`: a sibling document that fails to parse contributes no settings rather than propagating an error. `snapshotConfig()` is the single capture point for configuration switches, forks, clear, rewind and relocation; `applyConfig` re-injects the live view only when it is not reconfiguring from a fresh load, so a `/reload` result is never overwritten.

`runtime.ts` excludes `settingSources` from `connectionConfigDigest`, `liveConfigDigest` and the `buildTools` tool-set fingerprint. Provenance describes where accepted values came from; it never shapes a request, a connection or a tool schema, and a live save must not look like a different runtime owner.

## Boundaries

In-process dedicated writes only. External processes editing the same files, generic file tools, MCP enabled state, approvals and spinner history remain outside this event. Managed policy origins keep their accepted load snapshot; a successfully written explicit settings file that aliases a local document participates through the flag entry only. Presence is recomputed without a load: a sibling document that fails to parse contributes no live settings, while a fresh `loadProjectConfig` over the same tree raises `ConfigError` (existing loader behavior, unchanged here). Inherited startup behavior: `DiffPanel` rethrows a malformed user settings document during interactive startup, so a corrupted file still aborts resume; that owner is unchanged here.
