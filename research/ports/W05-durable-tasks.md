## Finite contract

Only standard HTTP creation writes mcp_task; fields server/configDigest/taskId/tool/createdAt/ttl/resolved and optional bounded JSON result/error flag. No arguments, credentials or HTTP session token recorded. At most128 unique records/session, two transitions per task; capacity blocks new MCP tool effects before execution. Digest pins workspace/server/definition. New sessions/forks/rewinds do not inherit task journals. Same IDs require matching creation and tool identity; duplicates rejected.
Creation ACK must fsync before foreground polling. Resolved original tool result validates first, then its JSON is bounded to24000UTF8bytes and journaled with isError separately; media/raw contents beyond bounded preview are not promised. On journal failure runtime is poisoned, all MCP effects/recovery blocked pending reconciliation. Remote ACK and local fsync remain nonatomic; a crash before durable ACK leaves unknown effects and no invented handle. stdio process restart recovery remains absent.
Explicit mcp_task_recover({}) lists local handles; server+taskId retrieves only journal-owned handles. Cached resolution returns without remote requests, retaining failures even when preview truncates. No remote list operation; remote missing/expired/access-denied remains unresolved. Retrieval checks taskId/schema and exact createdAt, only queries get/result, runs existing related callback ownership and fixed deadlines. Concurrent retrieval for one key blocked. Abort/close stop waiting without issuing tasks/cancel; normal foreground cancellation remains its existing behavior. Owner/scope/lifetime checks run before effects and before recovered result commit. It does not automatically replace original interrupted tool_result; normal Agent recovery first records unknown effect, then explicit tool retrieves saved result.
