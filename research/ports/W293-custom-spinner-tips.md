The source does not select a custom Tip at mount. markSubmit resets its pick latch; resetLoadingState and remote completion call the selector after a turn. A pending selection completing during a later active turn is held until idle. Bind/dispose invalidate the host's pending work; one owner retains the current Tip, latch and held publication. Config dialogs do not create agent progress events in this host.

The local file reader retains realpath, descriptor flags, regular-file check, 262144-byte cap, extra-byte read, finally-close and transient-error cache eviction. One cache belongs to the CLI process and survives config/session rebind. Trusted order is policy, flag, user; project/local accept strings only. Arrays retain the source filtering; objects are projected to id/text/cooldown/priority before entering session metadata so unknown settings fields stay outside the journal.

Source Ce/Ri/xi serializes read-modify-write under a filesystem lock. This host uses its copied lock library, existing write queue and atomic writer for a separate user-directory spinner-tips.json. It stores numStartups, tipsHistory and tipLifetimeShownCounts, never credentials or Tip text. The CLI increments once per user-directory owner; resume/reload within that directory and process does not increment. Concurrent processes re-read under the lock. Independent review exposed the source equality-only history update regressing under the host's fixed per-process startup. The adapter keeps max(last startup, this startup) and a successfully recorded per-startup id Set inside the file queue, retaining cooldown and lifetime counts under interleaving. Startup distances clamp at zero when a newer process has shown the id. Failed startup acquisitions leave the process cache so a repaired file can recover on the next pick. Source ranking and same-startup lifetime dedup are retained. A user-directory rebind closes the old selector, drains its pending successful writes and creates the new directory's owner; no Tip history crosses that boundary. Startup acquisition and retired-selector flushes share the terminal's pending Set, so closing under a held history lock still waits for initialization before flush returns.

The source managed loader accepts all settings; this host keeps policy and display projections separate. On-disk managed Tips are retained as policySettings layers without adding display data to managedPolicy. The three runtime digest exclusions and startup/reload/session schemas migrate together. Show tips writes local settings, then re-reads Qn/ft's effective merged gate before updating its live consumer, preserving higher flag/policy settings. Independent review reproduced and repaired a direct-row-value gate bypass. Show tips changes the selection gate. As in Cn, an already published custom Tip remains until the next completed turn clears it; timed vendor fallback text is excluded.

The built-in and marketplace catalogs are explicitly excluded by the user's local/neutral constraint. An empty or exhausted custom catalog therefore produces no Tip here, even where source hn would fall through to built-in tips. No substitute default text is invented. Native progress retains its existing task-list precedence; compaction/retry Tip precedence has no separate local producer in this surface. $e is adapted to native row/text layout; offscreen-lock/accessibility wrappers stay with the owned renderer.
