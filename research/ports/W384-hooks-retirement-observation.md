## Owned compiled observation

An owned compiled probe at content identity `fddd8431de9e1eecfab49dc5dce64420b20d79eab51c9c0624d6585b90040eb5` loaded two local fixture modules. Only the first registered `prompt.edit`; the probe explicitly replaced the second record's `retire()` with a throwing test function. After removal failed, both inventory and owner snapshots were empty for the fixture's `w384-` entries, `chainHooked('prompt.edit')` was false, the mounted relay still recorded, and the fixture listener's notification count was zero. A later empty reconciliation left that state unchanged. Restoring and invoking the injected record's real retirement, then explicitly notifying, released the relay. A normal two-module removal control left both fixture-filtered snapshots empty, set the relay's recording flag false and emitted exactly one notification to the fixture listener. Probe SHA-256 `f6573f928d9893644f0d3fd47f7feb3fc363a4c67ee37de1a8e117bd4ffea6cd`; output `3b8f57ed6ad58c57c285d77e44e8d0e40e78efaf5c52881f131428e8f4a32d31`. Its owned directory was removed. This demonstrates a host consequence of an injected exception; it does not show a normal user workflow can produce the exception.

The source's `iF` also stops before its notification if `retire` throws. The host and source differ in per-record versus whole-set inventory removal on that exceptional path, as W382 records. No recovered body establishes a retry notification in this case, and no ordinary production throw has been established. A symptom-driven retry or `finally` notification would therefore introduce an unverified divergence. This package records the observed boundary instead of changing product behavior. Existing `test/plugin-hooks-queue.test.ts` passes 9/9 at the same product/test/build identity; output SHA-256 `7604363d241660fe7a4a0038113304c34c78e0a1c2fdce7c7b866dd78d2f8d7c`. It covers the earlier first-retirement owner boundary, not this forced second-retirement observation.

An independent static reader checked `iF`, the registry, loader, relay, fixture and captured output. It identified an inaccurate initial task-card description of the second module and noted that snapshots filter only fixture-owned names; both descriptions are corrected above. It confirmed that a synchronous throw prevents the later direct notification calls within `iF`, without ruling out effects from earlier helpers. It did not rerun code, verify digests or establish production reachability. The review used 33 tool calls; its result is scoped to the inspected source and captured evidence.
